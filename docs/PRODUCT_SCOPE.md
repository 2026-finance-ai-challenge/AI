# AI 제품 범위

## 역할

Backend가 검증·최소화한 데이터만 받아 OpenAI Responses API로 영어 번역·요약·설명·답변을 생성한다. 뉴스 분류는 생성 모델과 분리해 검증된 Hana 금융 모델과 K-FNSPID 모델로 처리한다. AI 서비스는 브라우저에 직접 노출하지 않으며 시장·사용자 영속 상태와 인증은 Backend가 관리한다.

## 구현 기능

| 영역 | 입력 | 검증 출력 |
| --- | --- | --- |
| 제목 번역 | 고유 한국어 뉴스·공시 제목 배치 | 입력 ID별 영어 제목, 원문 해시, 모델·프롬프트 버전 |
| 뉴스 생성 | 사용자 요청 시 제공된 기사 본문 | EN 본문·What/Why/Impact, KR What/Why/Impact, 모델·프롬프트 버전 |
| 뉴스 분류 | 정규화한 제목·본문 | Hana 이벤트·감성·의미 중요도, K-FNSPID 시장영향 중요도·점수, confidence |
| 금융 용어 | 선택 문장, 기사 문맥, 검증 근거 | 영문 정의, 문맥 해설, 근거, confidence |
| 공시 요약 | 고정된 접수번호·문서 버전의 문단·표 | What/Why/Impact와 문단·표 인용 |
| 공시 섹션 번역 | 고정된 접수번호·문서 버전의 한 섹션 | 구조·수치·표를 보존한 영어 번역 |
| 공시 RAG | 공시별 HALFVEC 검색 근거와 현재 질문 | 질문 언어의 EN/KR 답변, 주장별 인용, 근거 부족 상태 |
| 시장 Agent | Backend가 조회한 시세·뉴스·공시·세무 문맥 | 출처·기준 시각이 연결된 안내 답변 |
| 세무 OCR | 복호화된 허용 문서 바이트와 기대 문서 유형 | 필드, 누락, 문서 간 불일치, 위험도, 검증 상태 |
| 글로벌 피어 | 검증된 사업·산업·재무 참고 카탈로그 | 대표 피어, 3개 비교 차원, 4개 강점, 근거·confidence |

## 운영 원칙

- OpenAI 호출은 `store=false`를 기본값으로 한다.
- 이벤트·감성·의미 중요도·시장영향 중요도는 OpenAI가 생성하지 않으며, 분류 실패 시 생성 모델로 대체하지 않는다.
- Hana 프로젝트는 읽기 전용으로 마운트하고 허용 Git commit과 핵심 모델 SHA-256이 모두 일치할 때만 로드한다.
- KF-DeBERTa v6 후보는 공식 gate가 `KEEP_CURRENT_MODEL`인 동안 활성 모델로 승격하지 않는다.
- 모델 ID와 프롬프트 버전은 환경 설정으로 주입하고 모든 응답 메타데이터에 기록한다.
- 구조화 결과는 Pydantic/JSON Schema의 필드 수·열거형·인용 형식까지 검증한다.
- 뉴스·공시·사용자 텍스트는 명령이 아닌 신뢰할 수 없는 데이터 경계 안에 넣는다.
- 현재가, 거래 상태, 외국인 한도와 같은 최신 사실은 Backend 도구 결과 없이는 생성하지 않는다.
- 공시 검색 범위는 접수번호·문서 버전으로 격리하고 검색 근거가 부족하면 답변을 거절한다.
- 일반·종목 채팅의 공시 질문은 내부 `/internal/v1/disclosures/evidence`에서 지원 종목·기간을 제한해 검색한다. 실적 질문은 최신 실적 보고서를 먼저 찾고 연결 손익·기간·단위를 포함한 원문과 현재 벡터 청크를 함께 검색한다. 임베딩 복구 대기 문서는 현재 원문만 검색하며 이전 버전 청크는 사용하지 않는다. 검색 자체는 답변 LLM을 호출하지 않는다.
- 뉴스 재요청은 같은 원문의 검증된 양언어 요약을 보존하고 본문만 생성할 수 있다. 부분 스트림을 완성된 본문으로 저장하지 않는다.
- 본문은 문장 단위로 번역하고 원래 문단으로 재조립한다. 원화 금액은 표기 순서·쉼표·영문 단위가 달라도 값이 정확히 같으면 인정하며 누락·다른 통화·금액 변조는 거절한다.
- 제목은 제한된 고유 텍스트 배치로 번역하고, 뉴스 본문·Insight와 공시 섹션은 Backend가 검증한 최초 사용 요청에만 생성한다. 데이터 수집 시 본문 전체를 번역하지 않는다.
- 공시 RAG는 번역본이 아닌 한글 원문을 다국어 임베딩으로 검색한다. 일반·뉴스·공시 채팅의 기본 `answer_locale=auto`는 질문만 로컬 언어 판정한 뒤 해당 언어 스키마를 선택한다. 사이트 EN/KR·선택 인용문·이전 대화로 답변 언어를 정하지 않는다. EN/KR별 출력 스키마·인용 검증을 유지하며 언어 판정용 OpenAI 호출은 없다.
- 직접 식별자를 전달하지 않으며 Backend 전용 Bearer 토큰, 허용 호스트, 타임아웃과 제한된 재시도를 적용한다.
- 검증된 피어 참고 데이터가 없는 종목은 임의 결과를 만들지 않는다.

번역 생성 경계, 목표 내부 API와 RAG 언어 평가는 [번역 생성과 다국어 공시 RAG 기준](TRANSLATION_AND_RAG.md)을 따른다.

## 서비스 구성

- API 프로세스: 제목 배치, 온디맨드 뉴스·공시 번역, 요약·답변·OCR·피어 생성 요청 처리
- RAG 작업자: 공시 payload 청킹·임베딩·작업 큐 처리
- PostgreSQL: 구조화 payload, 검색 위치, HALFVEC, 작업 상태
- OpenAI: Responses API 기반 생성형 분석

## 완료 기준

- 일반 채팅은 현재 질문을 기준으로 답변하고 근거 부족을 판단한다. 대화 이력은 참조 해석에만 사용하며 재무 수치는 기간·연결/별도·단위를 섞지 않는다.
- 재무 근거는 저장된 표의 행·셀 순서와 앞선 기간·단위를 함께 전달한다. 검색용 청크 생성 기준과 진행 중인 임베딩 복구는 유지한다.
- 각 생성 기능의 정상·타임아웃·스키마 실패·근거 부족 경로와 분류 모델 무결성 실패 경로를 테스트한다.
- 정적 분석, 타입 검사와 전체 테스트를 통과한다.
- Backend와 같은 서비스 토큰으로 실행한 Docker 헬스체크와 Hana 실제 분류 추론을 통과한다.
- 수집과 본문 생성을 분리하고 제목 배치 무결성, 영문 질문→한글 공시 근거 검색·영어 답변 평가를 통과한다.
