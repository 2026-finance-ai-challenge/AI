# 번역 생성·공시 RAG 계약

개발 브랜치 기준, 2026-09-03. 영속 캐시·작업 소유권은 Backend가 관리하고 AI 서비스는 원문 해시·구조·언어·수치 검증을 담당한다.

## 생성 경로

| 내부 API | 역할 |
| --- | --- |
| POST /internal/v1/translations/titles | 고유 제목의 영어 배치 번역 |
| POST /internal/v1/news/narratives/stream | 원문 기반 EN/KR 요약과 영어 본문을 한 번에 생성, NDJSON 진행 전달 |
| POST /internal/v1/news/narratives | 이전 작업·기존 호출을 위한 언어별 호환 경로 |
| POST /internal/v1/disclosures/section-translations | 공시 섹션·표 셀의 영어 번역 |
| POST /internal/v1/disclosures/summaries | 공시 원문 기반 EN/KR What / Why / Impact 동시 생성 |
| POST /internal/v1/disclosures/{receiptNumber}/questions | 한글 공시 검색 근거 기반 답변·인용 |

생성 모델은 gpt-5-nano다. 금융 분류·시장영향 및 임베딩 모델은 생성 모델과 별개이며 승인된 모델·revision을 사용한다.

## 뉴스 한 번 생성

news-bilingual-v1 요청은 원문 한국어를 기준으로 summaries.en, summaries.ko를 먼저 생성하고 문단별 영어 번역을 이어서 생성한다. news-bilingual-stream-v4 프롬프트는 각 항목 한 문장, 영어 18단어 목표·최대 24단어/180자, 한국어 90자 이내로 제한한다. 법인 표기·인용문도 영어로 번역하며 한글을 괄호 안에 복사하지 않는다. 길이를 넘는 문장을 사후 절단해 금액 단위나 의미를 잃게 하지 않고 검증 실패로 처리한다. 이유·영향이 원문에 없으면 없다고 명시하며 추론으로 채우지 않는다.

금액 토큰은 원문 구간별로 보호한다. 영어는 KRW와 million/billion/trillion, 한국어는 원문의 조·억·만 표현으로 복원한다. 법 조항 번호와 톤·면적·전력 단위를 통화로 오인하지 않는다.

완전한 요약 객체가 스키마·언어 검증을 통과하면 summaryReady 이벤트를 보낸다. 본문은 문단 ID·순서·개수·통화 토큰을 모두 확인한 후 bodyReady 완료 이벤트로 보낸다. 요약과 본문은 같은 공급자 호출에서 나온다. 요청 원문 총 길이는 180,000자로 제한하며 긴 입력을 무제한 호출로 쪼개지 않는다.

구버전 비스트리밍 경로는 진행 중인 기존 작업과 호환하기 위해 유지한다. 새 Backend 작업은 스트리밍 경로를 사용한다. Naver 검색 요약을 기사 전문이라고 표시하지 않는다.

## 공시 번역

- heading·text·table JSON의 원문 해시를 재검증한다.
- 표의 입력 ID·행·셀 개수·빈 셀을 보존한다. 내용 있는 셀의 빈 번역은 거절한다.
- 표의 큰 입력은 최대 18개·4,500자씩 나누고 동시 요청을 제한한다.
- 회사명·부서명·짧은 라벨과 꺾쇠 안의 가시 텍스트도 영어로 번역한다. 영문 필드 스키마는 한글·CJK 잔존을 거절한다.
- 한국식 금액·수량은 정확한 값으로 정규화·보호한다. 누락된 금액을 결과 끝에 덧붙여 성공 처리하지 않는다.
- 공식 기관명 구분은 [금융위원회 소개](https://www.fsc.go.kr/eng/ab010101)를 기준으로 프롬프트에 명시한다.
- 제목 프롬프트는 financial-title-translation-v13, 섹션은 disclosure-section-translation-v7다. 제목은 gpt-5-nano/low와 짧은 내부 ID를 사용하며 해시는 서버가 검증한다. 괄호·인용문의 한글도 번역하고, 잘린 태그는 보이는 부분만 음역하도록 명시한다. 證·증은 Securities로 해석하며 弗는 달러로 정규화해 원화 금액으로 보호하지 않는다. 두산에너빌리티의 `8만빌리티` 같은 가격 별칭은 금액 토큰화 전에 `8만원 주가 수준`으로 풀어 써 단어 조각이 남지 않게 한다. 영어 문장은 모델이 생성하고, 금액 뒤에 불완전한 별칭 조각을 붙인 결과는 거절한다. Samjeonnix는 그대로 보존한다.
- 제목 생성 스키마는 ID·배치 길이·출력 가능한 ASCII 문자만 제한한다. 금액 토큰·청구 방향을 연결한 의미 정규식이나 광범위한 Unicode 부정 문자 집합을 생성에 사용하지 않는다. ASCII 지침에 따라 따옴표·말줄임·화살표도 일관되게 번역하고, 반환 후 CJK·토큰 누락/중복/불명/순서·금액·명확한 청구 방향을 독립 검증한다. 반소·상호 청구는 추정하지 않으며 모든 의미 오류를 검증한다고 주장하지 않는다. 제목 문장은 모델이 번역하며 결정론적 문장으로 대체하지 않는다. 기존 READY 캐시는 일괄 재생성하지 않는다.
- filing-summary-v3는 한 번의 원문 요청으로 두 언어의 요약을 생성한다. Backend는 같은 행의 EN/KR 필드를 저장하고 언어 전환 시 재생성하지 않는다.
- 제목 프롬프트 버전은 AI 실행 코드가 소유한다. 이전 환경 변수로 버전을 덮어쓰지 않는다. 청구 방향 검증은 `damages claim of/for/worth 금액 from`처럼 금액 위치만 다른 올바른 문장을 허용하되 반대 방향의 동사는 계속 거절한다.

## 제한·보안

전체 생성 시간은 큐 대기와 모든 분할 작업을 포함해 180초다. 서비스 생성 요청은 동시 8개로 제한한다. 공급자 SDK 자동 재시도는 비활성이다. 잘못된 결과를 임의 영문으로 대체하지 않는다.

시장 Agent는 공통 클라이언트의 30초 제한을 사용하지 않는다. 호출별 최대 90초와 전체 작업 기한을 함께 적용해 Backend의 120초보다 먼저 종료한다. 시간 초과는 `AI_PROVIDER_TIMEOUT`으로 구분하며 한 요청을 자동 재생성하지 않는다. 공급자 오류 로그에는 예외 종류만 남긴다. 호출별 timeout 설정은 [OpenAI 공식 문서](https://developers.openai.com/api/docs/guides/flex-processing#api-request-timeouts)를 참고하되 Flex 모드는 사용하지 않는다.

모든 입력 기사·공시·사용자 선택문은 명령이 아닌 신뢰할 수 없는 자료로 취급한다. 내부 인증, 크기·ID·해시 검증, 구조화 출력, store=false를 적용한다. 키·원문·번역 전문은 로그에 남기지 않는다. 토큰·지연·모델·프롬프트 버전은 메타데이터로 기록한다.

영문 검증은 Jo 같은 인명을 통화 단위로 오인하지 않도록 숫자 또는 won과 결합한 단위 표기를 검사한다. 제목·섹션 생성은 공급자 완료 상태를 확인한 다음 JSON을 파싱하며, 조기 종료는 AI_GENERATION_INCOMPLETE로 구분한다. 미완료 응답을 임의로 완성하거나 자동 재시도하지 않는다.

표 셀 ID 누락·중복·알 수 없는 ID, 빈 번역, 영문 검증 실패, 금액 토큰 누락·불명은 서로 다른 진단 사유로 기록한다. 로그에 원문·번역문을 넣지 않으며 공개 오류 코드는 기존 `AI_INVALID_OUTPUT`을 유지한다. 진단 재실행이 성공했다는 이유만으로 이전 실패의 근본 원인이 해결됐다고 판단하지 않는다.

제목도 ID 누락·중복·불명, CJK·금액 단위·보호 용어 위반을 구분하고 검증한 원문 해시로 작업을 연결한다. 공급자 조기 종료는 스키마 종류·반환 모델·요청/응답 ID·출력/추론 토큰을 기록한다. `max_output_tokens` 중단 사유만 보고 설정 상한 부족으로 단정하거나 상한을 늘리지 않는다. 종료 상태와 검증 실패는 [Structured Outputs 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs)에 따라 분리하며, 이 진단 보강은 자동 재시도나 완료 판정을 변경하지 않는다.

## RAG

한글 원문을 구조 보존 청크로 나누고 고정 다국어 임베딩으로 색인한다. 질문과 같은 공시·문서 버전의 근거만 답변에 제공하며, 허용 인용 ID 없는 주장을 거절한다. 공시 화면의 영어 번역을 검색 원문으로 사용하지 않는다. 임베딩 모델은 별도 평가·재색인 계획 없이 변경하지 않는다.

공시 선택 질문은 실제 `section_id`와 `text`를 받는다. 원문 선택은 현재 섹션과 비교한다. 영어 선택은 Backend가 확인한 `translation_source_hash`를 받아 READY·en·현재 정책 버전의 캐시를 조회하고, SHA-256·한국어 원문·제목·영어 선택문을 다시 검증한다. 실패·누락 캐시로 선택을 인정하거나 이를 위해 번역을 새로 생성하지 않는다. 선택 섹션은 검색 우선순위에만 사용하고 원문 근거·인용 검증을 유지한다.

API와 색인 워커는 모델 캐시 볼륨을 공유한다. API 시작 시 임베딩 모델을 준비한 뒤 준비 상태를 열어, 읽기 전용 루트 파일시스템의 다운로드 실패가 최초 질문까지 숨겨지지 않게 한다. filing-grounded-v5는 영어 문장과 문장별 출처 ID를 구조화해 받고 서버가 허용 출처를 검증한 뒤 인용 표시를 조합한다. 모델이 본문 괄호 표시를 빠뜨렸다는 이유만으로 근거가 있는 답변을 거절하지 않는다. 법인 표기까지 영어로 번역하고, 질문과 무관한 표 전체를 재현하지 않고 최대 세 문장으로 답한다. 복합 질문은 근거가 있는 부분을 답하고 없는 영향은 명시한다. 응답 완료 상태를 확인한 뒤 JSON을 검증하며 중단·스키마 오류 로그에는 원문이나 질문을 남기지 않는다. 이전 버전 색인 작업은 현재 문서 버전을 덮어쓰지 않는다.

filing-grounded-v8와 market-agent-v7의 기본 언어 정책은 `auto`다. 질문만 [Lingua](https://github.com/pemistahl/lingua-py) 2.2.0으로 로컬 판정한 뒤 EN/KR 중 하나의 검증 스키마를 선택한다. 혼합 질문의 인용문·URL을 제외하고 영문 고유명사·한국어 종결 표현을 구분한다. 근거·과거 대화·사이트 언어는 판정 함수에 전달하지 않는다. 숫자·기호 질문은 영어를 사용하며 기존 생성 작업의 en/ko는 호환 지원한다.

시장 Agent는 생성 단계에서 JSON 구조를 제한하고 완료된 응답에 언어·길이·값 범위 검증을 적용한다. Responses 완료 상태를 먼저 확인하며 불완전·거절 응답은 정상 답변으로 저장하지 않는다. 장애 로그에는 응답 ID·완료 상태·중단 사유·토큰 수만 기록하고 원문·질문·생성 답변은 남기지 않는다. 자동 재호출이나 임의 JSON 보정은 하지 않는다.

모델이 출력 언어까지 고르는 anyOf 구조는 제거했다. 영어 질문에 한국어 답변을 돌려준 실제 사례가 이 구조에서 통과했기 때문이다. 이제 출력은 서버가 독립적으로 결정한 언어와 스키마로 검증한다. 언어 판정용 OpenAI 호출·잘못된 출력의 자동 재생성은 없다. 공시 검색 근거가 없으면 같은 언어의 근거 부족 상태를 모델 호출 없이 반환한다. 상위 지침은 [OpenAI 지침 우선순위](https://developers.openai.com/api/docs/guides/prompt-engineering#message-roles-and-instruction-following)를 따른다.

공시 RAG와 시장 Agent는 답변 본문에 URL 대신 인용 ID를 반환한다. 출처 주소와 이동 버튼은 서버가 검증한 근거를 사용해 구성한다. 근거 부족 안내·주의 문구도 요청 언어로 제공하며 공시 원문 검색·선택문·인용 검증은 바꾸지 않는다.

## 검증

단위 테스트는 원문 해시, 잘못된 ID·누락·중복, 양언어 요약 조기 전달, 문단 경계, 금액 토큰, 영어 필드, 빈 셀, 시간 제한을 확인한다. 실제 운영 번역·RAG 질문 응답 검증은 Backend의 파이프라인 점검 기록과 구분하며 테스트 통과를 운영 배포 완료로 간주하지 않는다.
