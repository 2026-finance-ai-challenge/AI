# 번역 생성·공시 RAG 계약

개발 브랜치 기준, 2026-09-02. 영속 캐시·작업 소유권은 Backend가 관리하고 AI 서비스는 원문 해시·구조·언어·수치 검증을 담당한다.

## 생성 경로

| 내부 API | 역할 |
| --- | --- |
| POST /internal/v1/translations/titles | 고유 제목의 영어 배치 번역 |
| POST /internal/v1/news/narratives/stream | 원문 기반 EN/KR 요약과 영어 본문을 한 번에 생성, NDJSON 진행 전달 |
| POST /internal/v1/news/narratives | 이전 작업·기존 호출을 위한 언어별 호환 경로 |
| POST /internal/v1/disclosures/section-translations | 공시 섹션·표 셀의 영어 번역 |
| POST /internal/v1/disclosures/summaries | 공시 원문 기반 EN/KR What / Why / Impact 동시 생성 |
| POST /internal/v1/disclosures/{receiptNumber}/questions | 한글 공시 검색 근거 기반 답변·인용 |

생성 모델은 gpt-5-nano다. 금융 분류·시장영향 및 임베딩 모델은 생성 모델과 별개이며 승인된 모델·revision을 사용한다.

## 뉴스 한 번 생성

news-bilingual-v1 요청은 원문 한국어를 기준으로 summaries.en, summaries.ko를 먼저 생성하고 문단별 영어 번역을 이어서 생성한다. news-bilingual-stream-v3 프롬프트는 각 항목 한 문장, 영어 18단어 목표·최대 24단어/180자, 한국어 90자 이내로 제한한다. 길이를 넘는 문장을 사후 절단해 금액 단위나 의미를 잃게 하지 않고 검증 실패로 처리한다. 이유·영향이 원문에 없으면 없다고 명시하며 추론으로 채우지 않는다.

금액 토큰은 원문 구간별로 보호한다. 영어는 KRW와 million/billion/trillion, 한국어는 원문의 조·억·만 표현으로 복원한다. 법 조항 번호와 톤·면적·전력 단위를 통화로 오인하지 않는다.

완전한 요약 객체가 스키마·언어 검증을 통과하면 summaryReady 이벤트를 보낸다. 본문은 문단 ID·순서·개수·통화 토큰을 모두 확인한 후 bodyReady 완료 이벤트로 보낸다. 요약과 본문은 같은 공급자 호출에서 나온다. 요청 원문 총 길이는 180,000자로 제한하며 긴 입력을 무제한 호출로 쪼개지 않는다.

구버전 비스트리밍 경로는 진행 중인 기존 작업과 호환하기 위해 유지한다. 새 Backend 작업은 스트리밍 경로를 사용한다. Naver 검색 요약을 기사 전문이라고 표시하지 않는다.

## 공시 번역

- heading·text·table JSON의 원문 해시를 재검증한다.
- 표의 입력 ID·행·셀 개수·빈 셀을 보존한다. 내용 있는 셀의 빈 번역은 거절한다.
- 표의 큰 입력은 최대 18개·4,500자씩 나누고 동시 요청을 제한한다.
- 회사명·부서명·짧은 라벨과 꺾쇠 안의 가시 텍스트도 영어로 번역한다. 영문 필드 스키마는 한글·CJK 잔존을 거절한다.
- 한국식 금액·수량은 정확한 값으로 정규화·보호한다. 누락된 금액을 결과 끝에 덧붙여 성공 처리하지 않는다.
- 공식 기관명 구분은 [금융위원회 소개](https://www.fsc.go.kr/eng/ab010101)를 기준으로 프롬프트에 명시한다.
- 제목 프롬프트는 financial-title-translation-v8, 섹션은 disclosure-section-translation-v7다. 제목은 minimal 추론으로 짧은 내부 ID와 실제 번역만 생성한다. 원문 해시는 호출 전 서버에서 검증하고 응답에 직접 연결해 모델의 해시 복사 오류와 불필요한 토큰 생성을 방지한다.
- filing-summary-v3는 한 번의 원문 요청으로 두 언어의 요약을 생성한다. Backend는 같은 행의 EN/KR 필드를 저장하고 언어 전환 시 재생성하지 않는다.

## 제한·보안

전체 생성 시간은 큐 대기와 모든 분할 작업을 포함해 180초다. 서비스 생성 요청은 동시 8개로 제한한다. 공급자 SDK 자동 재시도는 비활성이다. 잘못된 결과를 임의 영문으로 대체하지 않는다.

모든 입력 기사·공시·사용자 선택문은 명령이 아닌 신뢰할 수 없는 자료로 취급한다. 내부 인증, 크기·ID·해시 검증, 구조화 출력, store=false를 적용한다. 키·원문·번역 전문은 로그에 남기지 않는다. 토큰·지연·모델·프롬프트 버전은 메타데이터로 기록한다.

영문 검증은 Jo 같은 인명을 통화 단위로 오인하지 않도록 숫자 또는 won과 결합한 단위 표기를 검사한다. 제목·섹션 생성은 공급자 완료 상태를 확인한 다음 JSON을 파싱하며, 조기 종료는 AI_GENERATION_INCOMPLETE로 구분한다. 미완료 응답을 임의로 완성하거나 자동 재시도하지 않는다.

## RAG

한글 원문을 구조 보존 청크로 나누고 고정 다국어 임베딩으로 색인한다. 질문과 같은 공시·문서 버전의 근거만 답변에 제공하며, 허용 인용 ID 없는 주장을 거절한다. 공시 화면의 영어 번역을 검색 원문으로 사용하지 않는다. 임베딩 모델은 별도 평가·재색인 계획 없이 변경하지 않는다.

API와 색인 워커는 모델 캐시 볼륨을 공유한다. API 시작 시 임베딩 모델을 준비한 뒤 준비 상태를 열어, 읽기 전용 루트 파일시스템의 다운로드 실패가 최초 질문까지 숨겨지지 않게 한다. filing-grounded-v2는 영어 응답 스키마와 원문 라벨 번역 지침을 적용하고 결과 언어를 검증한다. 이전 버전 색인 작업은 현재 문서 버전을 덮어쓰지 않는다.

## 검증

단위 테스트는 원문 해시, 잘못된 ID·누락·중복, 양언어 요약 조기 전달, 문단 경계, 금액 토큰, 영어 필드, 빈 셀, 시간 제한을 확인한다. 실제 운영 번역·RAG 질문 응답 검증은 Backend의 파이프라인 점검 기록과 구분하며 테스트 통과를 운영 배포 완료로 간주하지 않는다.
