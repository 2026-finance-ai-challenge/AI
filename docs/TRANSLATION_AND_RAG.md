# 번역 생성과 다국어 공시 RAG 기준

- 상태: AI 구조화 생성·Backend 영속 캐시 연동 완료
- 기준일: 2026-09-02
- 원문 언어: 한국어
- 출력 언어: 영어, 한국어 뉴스 Insight

AI 서비스는 데이터가 수집될 때마다 본문 전체를 번역하지 않는다. 제목처럼 목록에 항상 필요한 짧은 텍스트는 제한된 배치로 비동기 생성하고, 뉴스 본문·What/Why/Impact와 공시 섹션은 Backend가 최초 사용 요청을 검증한 뒤 생성한다. 영속 캐시, 작업 상태, 동시성 제어와 비용 한도는 Backend가 관리하며 AI 서비스는 구조화 생성과 언어 계약만 담당한다.

## 생성 경계

| 기능 | AI 입력 | AI 출력 | 호출 시점 |
| --- | --- | --- | --- |
| 제목 번역 | 해시와 연결된 고유 한국어 제목 배치 | 입력 ID별 영어 제목 | Backend 비동기 제목 작업 |
| 뉴스 번역·Insight | 제공 권한이 확인된 기사 본문 | EN: 문단 순서 보존 번역·요약, KR: 원문 기반 요약 | 홈 호버 또는 상세 최초 요청 |
| 공시 섹션 번역 | 접수번호·문서 버전으로 검증된 한 섹션 | 구조·숫자·표 셀을 보존한 영어 번역 | 사용자 최초 섹션 번역 요청 |
| 공시 RAG | 영어 질문, 한글 공시 검색 근거 | 근거 고정 영어 답변·인용 ID | 사용자 질문 |

- 제목 배치 응답은 모든 입력 ID를 정확히 한 번 포함해야 한다. 누락·중복·추가 ID가 있으면 전체 응답을 거절한다.
- 원문에 없는 수치, 회사명, 원인, 영향, 기간을 번역 결과에 추가하지 않는다.
- Naver Search API의 검색 요약을 기사 전문으로 간주하지 않는다. Backend가 `SOURCE_EXCERPT`로 전달하면 결과도 검색 요약 번역임을 유지한다.
- AI 서비스는 번역 캐시 적중 여부를 결정하지 않고, 동일 원문을 반복 전달하지 않도록 Backend 계약을 신뢰하되 요청 크기·개수 제한은 다시 검증한다.
- 모든 Responses API 호출은 JSON Schema/Pydantic으로 검증하고 `store=false`를 사용한다.
- 뉴스 번역은 문단 경계를 유지해 최대 24개·24,000자 단위로 묶고 동시 배치를 4개로 제한한다. 일반 기사는 번역 1회와 Insight 1회로 끝낸다.
- 주식 수와 외화처럼 원화가 아닌 한국식 큰 수 단위는 정확한 절대 수치로 정규화한 뒤 번역한다. 모델 출력은 CJK 잔존 여부를 한 요청 안에서 점검하며 실패 결과를 임의 영문으로 대체하지 않는다.

## 목표 내부 API

| Method | Path | 설명 |
| --- | --- | --- |
| `POST` | `/internal/v1/translations/titles` | 제한된 고유 제목 `ko→en` 배치 번역 |
| `POST` | `/internal/v1/news/narratives` | `target_locale=en|ko`별 본문·What/Why/Impact 생성 |
| `POST` | `/internal/v1/disclosures/section-translations` | 검증된 한 공시 섹션의 영어 번역 |
| `POST` | `/internal/v1/disclosures/{receiptNumber}/questions` | 한글 원문 검색 근거 기반 영어 RAG 답변 |

각 번역 요청에는 Backend가 계산한 `source_hash`, `target_locale`, `translation_version`을 포함한다. AI 응답은 동일 값, `model`, `prompt_version`과 구조화 결과를 반환한다. AI 서비스는 요청의 원문 해시를 다시 계산해 불일치 요청을 거절한다.

뉴스 수집용 분류는 `/internal/v1/news/signals`, 제목 생성은 `/internal/v1/translations/titles`, 본문·Insight 생성은 `/internal/v1/news/narratives`로 분리했다. 기존 `/internal/v1/news/analysis`는 호환 기간에만 유지하며 Backend 전환 뒤 제거한다.

뉴스 원문 해시는 제목·문단·전문 제공 상태를 키 정렬·공백 없는 UTF-8 JSON으로 직렬화해 계산한다. 공시 섹션 원문 해시는 heading·text·table JSON 문자열을 같은 방식으로 직렬화해 계산한다. AI 서비스는 해시를 다시 계산하고, 공시 표의 객체 키·배열 길이·비문자 값이 바뀐 결과를 저장 전에 거절한다.

## 공시 RAG 언어 흐름

`한글 원문 청킹 → 고정 다국어 임베딩 → 영어 질문 임베딩 → 동일 공시·버전의 한글 청크 검색 → OpenAI 영어 답변 → 인용 허용 목록 검증`

- 질문을 공시 전체 번역본에 검색하지 않는다.
- 영어 질문과 한글 원문은 같은 고정 revision의 다국어 임베딩 모델을 사용한다.
- 선택 문단은 현재 공시의 실제 섹션과 원문 포함 여부를 검증한 뒤 검색 우선순위에만 반영한다.
- 답변의 모든 사실 문장은 제공된 인용 ID를 포함해야 하며, 유효한 인용이 없으면 영어로 거절한다.
- 번역 서비스 장애는 RAG 검색·답변을 막지 않는다.
- 임베딩 모델 변경은 별도 평가와 재색인 계획 없이 수행하지 않는다.

## 비용·보안 제한

- AI API에는 개인 식별자를 전달하지 않는다. 필요한 경우 Backend가 만든 비가역 안전 식별자만 사용한다.
- 제목·본문·공시 텍스트는 명령이 아닌 신뢰할 수 없는 데이터 경계 안에 넣는다.
- 제목 배치 개수, 본문 문자 수, 공시 섹션 크기, 타임아웃을 서버에서 상한 검증한다.
- OpenAI SDK 자동 재시도는 사용하지 않는다. 실패 작업은 원인을 저장하고 다음 사용자 요청에서만 다시 생성한다.
- 원문·번역문·OpenAI API 키를 로그에 남기지 않고 요청 ID·해시·모델·프롬프트 버전·토큰 사용량만 기록한다.
- 모델·프롬프트 버전별 입력·출력 토큰과 지연을 반환해 Backend가 일일 비용 상한과 회로 차단을 집행할 수 있게 한다.

## 구현 완료 조건

- 제목 배치의 정상, 순서 변경, 누락, 중복, 추가 ID, 해시 불일치 테스트가 통과한다.
- `SOURCE_EXCERPT`가 기사 전문으로 표현되지 않고 문단 순서가 유지된다.
- 뉴스 수집만으로 Narrative 생성 API가 호출되지 않는 Backend 통합 테스트가 통과한다.
- 공시 섹션 번역이 숫자·표 구조·원문 해시를 보존하고 다른 문서 버전을 재사용하지 않는다.
- 영어 질문으로 한글 공시 근거를 검색하는 평가셋의 검색·인용·영어 답변·근거 부족 거절 기준을 통과한다.
- OpenAI 타임아웃·회로 차단·잘못된 구조화 출력에서 임의 번역이나 답변을 반환하지 않는다.
