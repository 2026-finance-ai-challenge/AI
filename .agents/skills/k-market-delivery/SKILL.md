# K-Market 개발·전달 절차

1. `AGENTS.md`, `docs/PRODUCT_SCOPE.md`, `docs/GIT_WORKFLOW.md`를 읽는다. 번역·뉴스·공시·RAG 작업이면 `docs/TRANSLATION_AND_RAG.md`도 읽는다.
2. Git 상태를 확인하고 최신 `dev` 기반 작업 브랜치를 사용한다.
3. 요청 범위만 구현하고 테스트·타입 검사·RAG 평가를 실행한다.
4. 변경 내역, 검증 결과, 남은 위험을 사용자에게 제시한다.
5. 사용자 승인 전까지 커밋·푸시·PR·병합을 보류한다.
6. 승인 후 한글 명사형 제목으로 커밋한다. `dev` PR 병합을 마치면 작업 브랜치를 삭제한다.

## 번역·RAG 변경 검증

- 제목 배치와 뉴스 Narrative·공시 섹션 번역 계약을 분리하고 본문 일괄 선번역 경로를 만들지 않는다.
- 입력 ID·개수·원문 SHA-256·대상 언어·번역 정책 버전을 재검증하고 불일치 응답을 저장 가능한 결과로 반환하지 않는다.
- Naver 검색 요약을 기사 전문으로 표현하지 않는다.
- 공시 RAG는 한글 원문 다국어 검색과 영어 답변·유효 인용을 유지하며 번역 캐시 장애와 분리한다.
- 구조화 출력, `store=false`, 프롬프트 주입 경계, 요청 크기 제한, 모델·프롬프트·토큰 메타데이터를 검증한다.
- 영문 질문→한글 근거 검색, 인용 일치, 근거 부족 거절 평가를 실행한다.
